## Calling quickrss before the MCP tool is exposed
- The `mcp__quickrss__*` tools do not appear in ToolSearch until the server is trusted + session
  reloaded. Workaround that works today: POST JSON-RPC directly to the endpoint.
- Helper script kept at `/tmp/qrss.py` (`tool(name, args)`), usage:
  `python3 /tmp/qrss.py search_articles '{"query":"Astra"}'`
- `search_articles` is a loose OR/fuzzy full-text match — it returns plenty of noise
  (e.g. "astray", "fastRAG"/DataStax Astra). Always post-filter on title+summary containing the
  literal keyword, and check the `link` slug too.

## Gotcha: `star` is a silent no-op outside the loaded view
- `star` / `unstar` / `star_all` / `unstar_all` only act on `loadedArticles` (what the UI is
  currently showing). `search_articles` / `get_unread_articles` read the full `articleDatabase`,
  so they happily return articles that CANNOT be starred.
- `star` returns `{"success":true}` even when the id was not found -> always verify with
  `get_starred_articles` afterwards.
- Safe probe for what is in view: `chat_with_news` ("how many articles are loaded, list feed
  titles"). Do NOT probe with `star_all`/`unstar_all` (destructive).
- Workaround: ask the user to click the relevant feed (or All/Latest) in the app window so the
  articles enter the view, then re-run `star` per article id.
- Starred state lives in localStorage via `setArticleStarred`; `get_starred_articles` reads it.

## MCP add_* quirks found while populating
- `add_folder` / `add_feed` generate ids from `Date.now()` — space calls ~60ms apart or ids collide.
- Both `unshift` into the parent, so children render in reverse insertion order. Insert reversed
  to get the intended display order.
- Occasional transient response with no `content` key; retry 2-3x. Write loops idempotently
  (re-read `get_feed_tree`, skip URLs already present) so a partial run is safe to re-run.
- `add_feed` triggers `fetchAndDisplayArticles`, which changes the app's loaded view as a side effect.
